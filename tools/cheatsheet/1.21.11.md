# Minecraft 1.21.11 + Fabric: verified facts (Mojang mappings)

Checked against the 1.21.11 game jar and the official reference mod; the code patterns compile (samples/smoke/cheatsheet).

## Names and packages
- Entrypoints: `net.fabricmc.api.ModInitializer` / `net.fabricmc.api.ClientModInitializer` (NOT net.fabricapi...).
- Ids: `net.minecraft.resources.Identifier.fromNamespaceAndPath(modId, path)`. `ResourceLocation` does NOT exist.
- Mojang names, never Yarn: `Level` (not World), `ServerPlayer` (not ServerPlayerEntity), `Component` (not Text),
  `BlockPlaceContext` (not ItemPlacementContext), `CreativeModeTab(s)` (not ItemGroup).
- `net.minecraft.core.BlockPos`, `net.minecraft.core.Direction`, `net.minecraft.ChatFormatting`,
  `net.minecraft.network.chat.Component`, `net.minecraft.world.level.material.MapColor`.

## Items
```java
ResourceKey<Item> key = ResourceKey.create(Registries.ITEM, Identifier.fromNamespaceAndPath(MOD_ID, "ruby"));
Item item = Registry.register(BuiltInRegistries.ITEM, key, new Item(new Item.Properties().setId(key)));
```
- `Item.Properties.setId(key)` is REQUIRED before constructing the item.
- `SwordItem`, `PickaxeItem`, `AxeItem`, `DiggerItem`, `ToolItem` do NOT exist. Tools are plain `Item`s:
  `new Item.Properties().sword(ToolMaterial.IRON, 3f, -2.4f)` (also `.pickaxe/.axe/.shovel/.hoe(material, dmg, speed)`).
- `ToolMaterial` is a record: `new ToolMaterial(TagKey<Block> incorrectBlocksForDrops, int durability, float speed,
  float attackDamageBonus, int enchantmentValue, TagKey<Item> repairItems)`; constants `ToolMaterial.WOOD/STONE/COPPER/IRON/DIAMOND/GOLD/NETHERITE`.
- Armor: `new Item.Properties().humanoidArmor(ArmorMaterials.IRON, ArmorType.HELMET)`
  (`net.minecraft.world.item.equipment.ArmorMaterials` / `ArmorType`).
- Food: `.food(FoodProperties)` (`net.minecraft.world.food.FoodProperties`). Other: `.durability(n)`, `.stacksTo(n)`, `.fireResistant()`, `.rarity(Rarity.RARE)`.
- `Item.use(Level, Player, InteractionHand)` returns `InteractionResult`. `InteractionResultHolder` does NOT exist.
- Every item needs `assets/<modid>/items/<name>.json`: `{"model": {"type": "minecraft:model", "model": "<modid>:item/<name>"}}`
  plus `assets/<modid>/models/item/<name>.json` and a lang entry `item.<modid>.<name>`.
- Creative tabs: `ItemGroupEvents.modifyEntriesEvent(CreativeModeTabs.INGREDIENTS).register(entries -> entries.accept(ITEM));`
  (`net.fabricmc.fabric.api.itemgroup.v1.ItemGroupEvents`).

## Blocks
```java
ResourceKey<Block> key = ResourceKey.create(Registries.BLOCK, Identifier.fromNamespaceAndPath(MOD_ID, "copper_coil"));
Block block = Registry.register(BuiltInRegistries.BLOCK, key,
        new Block(BlockBehaviour.Properties.of().setId(key).mapColor(MapColor.COLOR_ORANGE).strength(3f, 6f)));
ResourceKey<Item> itemKey = ResourceKey.create(Registries.ITEM, key.identifier());
Registry.register(BuiltInRegistries.ITEM, itemKey, new BlockItem(block, new Item.Properties().setId(itemKey).useBlockDescriptionPrefix()));
```
- `BlockBehaviour.Properties.setId(key)` is REQUIRED. `Material` and `MaterialColor` do NOT exist: use `.mapColor(MapColor.X)`.
- `DirectionProperty` does NOT exist: facing is `EnumProperty<Direction>`, e.g. `BlockStateProperties.HORIZONTAL_FACING`.
- Overridable (protected) methods: `createBlockStateDefinition(StateDefinition.Builder<Block, BlockState>)`,
  `useWithoutItem(BlockState, Level, BlockPos, Player, BlockHitResult)` returning `InteractionResult`,
  `getStateForPlacement(BlockPlaceContext)` (public).
- Subclasses of abstract blocks like `HorizontalDirectionalBlock` must implement `protected MapCodec<? extends ...> codec()`
  (e.g. `return simpleCodec(MyBlock::new);`).
- Blocks need `assets/<modid>/blockstates/<name>.json`, `models/block/<name>.json`, an item model definition in
  `assets/<modid>/items/<name>.json`, and a lang entry `block.<modid>.<name>`.

## Commands
```java
CommandRegistrationCallback.EVENT.register((dispatcher, registryAccess, environment) ->
        dispatcher.register(Commands.literal("home")
                .requires(source -> source.permissions().hasPermission(Permissions.COMMANDS_MODERATOR))
                .executes(ctx -> {
                    ctx.getSource().sendSuccess(() -> Component.literal("Done"), false);
                    return 1;
                })));
```
- `net.fabricmc.fabric.api.command.v2.CommandRegistrationCallback`, `net.minecraft.commands.Commands`,
  `net.minecraft.commands.CommandSourceStack`, `net.minecraft.server.permissions.Permissions`.
- Permissions changed in 1.21.11: `hasPermissions(int)` / `hasPermissionLevel` are gone. Use
  `source.permissions().hasPermission(Permissions.COMMANDS_MODERATOR | COMMANDS_GAMEMASTER | COMMANDS_ADMIN | COMMANDS_OWNER)`.
- Old numeric op levels map to: 1 = `COMMANDS_MODERATOR`, 2 = `COMMANDS_GAMEMASTER`, 3 = `COMMANDS_ADMIN`,
  4 = `COMMANDS_OWNER`. A request for "level 4" just means `Permissions.COMMANDS_OWNER` - build it.
- Feedback: `source.sendSuccess(() -> Component.literal(...), false)`, `source.sendFailure(Component)`.
  Player: `source.getPlayer()` (nullable) or `source.getPlayerOrException()`.

## Block entities (from the official 1.21.11 reference mod)
```java
public static final BlockEntityType<CounterBlockEntity> COUNTER = Registry.register(BuiltInRegistries.BLOCK_ENTITY_TYPE,
        Identifier.fromNamespaceAndPath(MOD_ID, "counter"),
        FabricBlockEntityTypeBuilder.<CounterBlockEntity>create(CounterBlockEntity::new, ModBlocks.COUNTER_BLOCK).build());
```
- `net.fabricmc.fabric.api.object.builder.v1.block.entity.FabricBlockEntityTypeBuilder`. `BlockEntityType.Builder` is NOT used.
- Constructor: `super(ModBlockEntities.COUNTER, pos, state)`. Save/load:
  `protected void saveAdditional(ValueOutput output) { output.putInt("clicks", clicks); super.saveAdditional(output); }`
  `protected void loadAdditional(ValueInput input) { super.loadAdditional(input); clicks = input.getIntOr("clicks", 0); }`
  (No CompoundTag/HolderLookup parameters.)

## Entities and players
- `entity.level()` returns `Level`; on `ServerPlayer`, `level()` returns `ServerLevel`. `serverLevel()` does NOT exist.
- Messages to a player: `serverPlayer.sendSystemMessage(Component)`.
- Entity save/load methods take `ValueOutput` / `ValueInput` (`net.minecraft.world.level.storage`).
